# VIP Autonomous Multi-Target Local Validation v1

## Scope and governance

This report records bounded local validation only. The three campaigns used the existing VIP Autonomous Vertical Slice orchestrator and anonymous `GET` requests to explicit loopback origins. No credentials, payloads, state mutation, external contact, OAST callback, Bug Bounty target, or Official P10 run was used.

The official run gate remains closed: `official_isolated_p10_runs_authorized=false`. Human independent signoff remains absent. P10, P9, and VIP remain `NOT_QUALIFIED`; no scoring promotion or qualification claim was made.

## Execution result

All three campaigns reached the complete orchestrator lifecycle: campaign creation, scope validation, readiness, capability discovery, safe-case selection, baseline, bounded action, redacted observation, independent negative control, central oracle evaluation, ProofBundle decision, seal/replay stage, quality evaluation, diagnosis, improvement proposal, re-test/compare decision, and report generation.

Each campaign completed with an `observation_only` case status after a generic classification improvement. The central oracle correctly returned `inconclusive`, because a reachable root or health endpoint is not a causal vulnerability predicate; the outcome layer now explicitly labels the complete baseline-plus-negative-control result as observation-only. Independent negative-control contracts passed, while no ProofBundle was created for promotion because causal confirmation was absent. These outcomes are not counted as TP, FP, FN, clean, or confirmed findings.

## Detect → Diagnose → Improve → Re-test → Compare

The detected weakness was evidence insufficiency, not a confirmed vulnerability: the passive root/health observation has no admitted vulnerability-specific causal predicate. Diagnosis and Improvement Proposal were generated by the orchestrator. A safe generic classification improvement was implemented: complete non-causal observations are now explicitly `observation_only`, while incomplete evidence remains `inconclusive`. The change was regression-tested and re-run under the same conditions across all three Targets.

This remains fail-closed. The status label does not create a finding or authorize scoring. A target-local implementation remains inappropriate without a target-specific causal contract, and no generic discovery or causal oracle was invented from reachability alone. No frozen Ground Truth, threshold, policy, or governed scoring set was modified.

## Portability assessment

The same orchestrator executed against all three TargetSpecs without target-specific changes to ActionAuthority, CampaignExecutor, central verifier, or ProofBundle semantics. One generic outcome-classification change was applied and produced the same `observation_only` result on all three Targets. The only target-local data were the explicit origin, scope, source revision, readiness metadata, and campaign identity. This demonstrates transport, lifecycle, and outcome-label portability, but not vulnerability-detection quality portability: no Target had a valid additional scoring contract in this campaign.

## Remaining VIP gaps

The governed Juice Shop set remains 3 cases and 3 classes, leaving a gap of 7 cases and 3 classes against the P10 minimum. The classification improvement does not change this count. WebGoat and crAPI require independent source-to-ground-truth manifests, admitted causal-oracle contracts, safe preconditions, independent negative controls, and sealed/replayable ProofBundles before their cases can enter quality metrics. Three isolated Official P10 runs, metrics recomputation, independent final review, and a final qualification decision remain blocked by those prerequisites and by the closed run gate.
